Notes

Short write-ups on problems I've actually had to solve.

  • Why Unreal Android builds started crashing after API 33

    Android 13 tightened scoped storage, and Unreal's generated Java for file access wasn't ready for it. The crash showed up as an engine-level failure, not a gameplay bug. The fix lived in the UPL file and the Java the build generates, and the proof lived in ADB logs and Unreal Insights.

  • Getting MIDI from a phone into Unreal

    MIDI devices talk on native threads through platform APIs the engine knows nothing about. On Android that means JNI and a Java receiver; on iOS it means Objective-C. The interesting part is getting callbacks from those threads into the engine safely and with low enough latency to feel like an instrument.

  • Bounded GAS: where abilities stop and plain effects begin

    GAS is easy to over-apply. My current rule on a single-player project: attributes, gameplay effects, cues and tags everywhere; gameplay abilities only for discrete, montage-driven actions like reload, melee or a takedown. Movement, aiming, cover and camera stay out. The result is less boilerplate and far fewer surprises.
